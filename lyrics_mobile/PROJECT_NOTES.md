## 제품 목표

**Shazam 같은 음악 발견 앱에 곡 정보, 가사 번역·발음, 주간 추천, 카라오케 기능을 더한 종합 음악 앱**을 목표로 합니다.

주요 경험:
1. 휴대폰에서 재생 중인 곡 가져오기.
2. 주변에서 들리는 음악을 마이크로 인식하기.
3. 원곡 정보 및 가사·번역·발음 보기.
4. YouTube, Apple Music, Spotify에서 해당 곡/검색 결과 열기.
5. 저장된 기록과 곡 데이터 재사용하기.
6. 준비된 곡에 한해 음정 가이드와 노래 점수 제공하기.

## 사용자 확정 요구사항

### UI/UX
- 현재 UI를 전면 개선한다. 토스를 주요 디자인 참고 대상으로 삼고, 애플처럼 간결하고 세련되며 접근하기 쉬운 경험을 지향한다.
- 화면마다 핵심 행동을 분명히 하고, 적절한 여백·타이포그래피·색상·로딩/성공/실패 피드백을 일관되게 사용한다.
- 브랜드 화면을 그대로 복제하지 않고 디자인 원칙을 참고한다.
- **전체 UI와 주요 흐름을 먼저 정한 다음 가로/세로 레이아웃을 대응**한다.
- 접근성(큰 글꼴, 대비, 터치 영역, TalkBack)은 디자인 과정에서 고려한다.

### 두 가지 음악 감지 경로
- **현재 재생 곡 가져오기:** 휴대폰의 미디어 세션 등 공개된 재생 메타데이터 사용. 모든 앱이 정확한 곡 정보를 제공하는 것은 아니다.
- **주변 음악 듣고 찾기:** 사용자 동작으로 마이크를 켜 짧게 녹음하고 음악 인식 서비스로 식별한다. 기본안은 ACRCloud 검토.
- 음악과 무관한 알림을 곡으로 오인하지 않도록 현 알림 처리 구현을 고친다.
- 상시 청취는 현재 목표가 아니다. 사용자가 시작·취소를 제어하고 마이크 상태를 명확히 알 수 있어야 한다.

### 제목 정리, 원곡, 검색 실패
- YouTube 등의 부정형 메타데이터는 AI가 곡명·가수 후보를 추출/정리하도록 보조할 수 있다.
- AI의 제목 정리는 실제 음원 인식이 아니다. 카탈로그 검색 등으로 실제 곡을 검증한다.
- AI가 곡명/URL을 만들어내거나, 불확실한 후보를 성공으로 단정하지 않는다.
- **커버·라이브·리믹스는 초기에는 원곡 정보와 원곡 가사만 보여준다.**
- 원곡 대응을 확인할 수 없거나 곡을 식별하지 못하면 ‘찾지 못함’을 안내한다. 실제 버전과 원곡의 멜로디가 다를 수 있어 원곡 음정 데이터로 커버/라이브를 채점하지 않는다.
- 곡 없음, 네트워크 오류, 인증/쿼터 오류, 가사 없음은 내부적으로 구분해 적절한 안내를 제공한다.
- 앱 내 안내 UI(예: Snackbar/Dialog 등)의 구체 형태와 최종 문구는 미정.

### ACRCloud
- 사용자가 자격정보를 입력하면 연결되는 기능 준비가 필요하다.
- ACRCloud Identification API는 단일 키가 아니라 보통 `host`, `access_key`, `access_secret`이 필요하다.
- 프로젝트 내 `app/src/main/java/com/example/lyrics_mobile/AcrCloudClient.java`에 요청 서명·오디오 전송·결과 파싱 코드가 있지만, 마이크 녹음 및 UI와 연결되지 않았다.
- 개발/개인 테스트용 키 입력은 가능하지만 기기 내 비밀키는 완전히 보호되지 않는다.
- 배포 서비스의 운영자 키는 APK에 넣지 말고 서버 환경에 보관하는 구조를 권장한다. 개발용 직접 연결과 서버 중계 중 어느 경로를 먼저 구현할지는 미정.
- 등록 단계: ACRCloud 계정 → Audio & Video Recognition 프로젝트 → 음악 카탈로그 연결 → Recorded Audio 설정 → credentials 확인 → 짧은 샘플 테스트.
- 짧은 버튼 기반 녹음(초기 제안 약 10초), 포맷/크기 제한, 요청 취소, 사용량 제한을 검토한다. 파일명을 WAV로 바꾸는 것만으로 WAV 변환되지는 않는다.
- ACRCloud는 곡 인식 서비스이지 곡 전체 보컬 음정표를 제공하는 서비스가 아니다.

### 데이터 캐시 및 추천
- 이미 확보한 곡 정보·가사·번역·발음은 저장하고 재사용해 중복 검색과 AI 토큰 사용을 줄인다.
- 기존 JSON 캐시가 있으나 TTL/용량 제한/버전 검증/원자적 저장 등 보완이 필요하다.
- 캐시 키는 곡/녹음 버전, 원문 해시, 번역 언어, 모델/프롬프트 버전 등을 고려한다.
- 실패 문구·잘린 AI 출력은 성공 데이터로 캐시하지 않는다. 가사 등 제공처 데이터의 저장·재배포 약관은 확인한다.
- 추천은 이전에 보여준 곡과 사용자 이력을 참고하고 **주 1회 갱신**한다.
- 추천 묶음과 제시 이력을 저장해 한 주 동안 불필요하게 재생성하지 않는 방향. 주간 기준(정해진 요일 vs 7일 간격)은 미정.

### 외부 서비스 링크
- 결과/상세에서 YouTube, Apple Music, Spotify 바로가기를 제공한다.
- 확인된 정확한 곡 URL을 우선 사용하고 없으면 곡명·가수 검색 URL을 제공한다. 검색 링크는 검색임을 명확히 표시한다.
- 앱 설치 시 앱으로, 미설치/미지원 시 웹으로 열기를 시도한다.
- 링크 제공이 해당 앱의 전체 음원 재생 권리나 SDK 접근을 의미하지 않는다.

## 카라오케 음정 데이터 — 대화에서 검토한 방향

원하는 기능: 시간에 따라 곡의 목표 음정이 표시되고, 사용자가 부르는 음정이 실시간으로 위아래 표시되며, 종료 후 점수를 보여준다.

### 목표 데이터 생성은 자체 분석이 가능

외부 악보를 사는 것만이 유일한 방법은 아니다. 권리가 있는 원음에서 다음 파이프라인을 시험할 수 있다.

```text
권리 확보 음원 → 보컬/반주 분리 → 보컬 음정·음표 추정
             → 코러스/오류 보정 → 시간 정렬·검수 → 곡별 데이터 저장
```

- 보컬 분리와 음정 추정은 별개 작업이다.
- 후보 도구: [Demucs](https://github.com/facebookresearch/demucs) (보컬 분리, MIT; 원본 저장소는 아카이브 상태), [Basic Pitch](https://github.com/spotify/basic-pitch) (오디오→음표/MIDI, Apache-2.0; 한 악기 입력에서 더 적합하다는 안내), pYIN 등 F0 추정기.
- `Demucs → Basic Pitch`는 검증할 실험 후보이지 정확도가 보장된 제품 파이프라인이 아니다. 코러스, 듀엣, 리버브, 악기 누출, 비브라토, 랩 때문에 자동 결과를 검수해야 한다.
- GPT/Gemini의 일반 오디오 이해/음성 전사와 정밀한 프레임별 음정 추적·보컬 분리는 다르다. 채점 정답은 LLM의 음명 추측에 맡기지 않고 전용 오디오 분석을 검증한다.
- 곡별 사전 분석 후 결과를 저장하면 매 노래마다 LLM 토큰을 쓸 필요가 없다. 서버/PC 연산·저장 비용은 별도 발생한다.
- ACRCloud의 짧은 샘플로 전체 곡의 음정표를 만들 수 없다. 전체 원음을 합법적으로 확보해야 한다.
- 도구 라이선스와 원음/가사/2차 분석 데이터의 상업적 권리는 별개다. 오픈소스 도구가 곡 이용권을 주는 것은 아니다.

### 채점 제약
- 목표 음정 데이터에는 시간·음높이·구간·신뢰도 등이 필요하다. 가사 타임스탬프만으로 음높이를 알 수 없다.
- 사용자의 마이크 음정은 기기에서 실시간 분석할 수 있다. LLM 호출은 실시간 pitch tracking에 적합하지 않다.
- 재생/마이크 지연, 블루투스, 스피커 반주 누출, 옥타브, 키 조절이 채점 정확도에 영향.
- 외부 서비스 링크만으로 그 음원을 앱에서 분석하거나 재생 위치를 정밀 제어할 수 없다.
- 초기에는 권리 확보한 짧은 샘플/자체 멜로디로 분리→추정→오버레이를 실험한 뒤, 지원곡만 카라오케 제공하는 것이 현실적이다.
- DALI 연구 데이터는 보컬 음표와 가사 정렬의 참고 자료지만 공식 조건이 비상업 연구용이므로 상용 카탈로그로 바로 사용할 수 없다. Lakh MIDI 또한 개별 파일 권리 및 보컬 트랙 품질 검토 없이 상업용 정답 데이터로 간주하지 않는다.

## 프로젝트 감사: 현재 부족한 점과 우려 사항

현재 감사는 코드 정적 확인 중심이며 실제 기기/실서비스 연동 검증은 아니다.

| 우선 | 문제/위험 | 근거 및 방향 |

| 중간 | 네트워크·검색 실패 원인 은폐 | 빈 목록/문자열로 실패 반환하는 코드 존재 |

| 중간 | Activity 책임 과다 및 상태 복원 부족 | 화면/네트워크/캐시/권한 집중, 회전 시 동적 상태 손실 위험 |

| 중간 | targetSdk 36 UI inset 미흡 | Android 15/16 edge-to-edge에서 시스템 UI 겹침 위험 |
| 중간 | 접근성·큰 글꼴 대응 부족 | 탭 선택 상태/일부 레이블 미흡, 화면 크기 검증 필요 |
| 낮음 | 오래된 의존성·미사용 자원·문서 부족 | 최신 호환성 중심 업데이트, 실제 사용 확인 후 정리 필요 |

## 권장 단계

1. 전체 정보 구조와 화면 흐름/디자인 결정(토스 참고, 접근성 포함).
2. 현재 재생 메타데이터와 주변 음악 인식을 분리해 완성하고 실패/상태 표시 구현.
3. ACRCloud 설정(개발용 자격정보 입력 또는 서버 중계)·녹음·보안·사용량 한도 결정.
4. 곡 검증/원곡 대응, 가사/번역/서비스 링크를 곡 상세에 통합.
5. 캐시/보관함/최근 인식/주간 추천 구현.
6. 카라오케는 권리 확보한 곡으로 음정 생성 파이프라인을 별도 검증 후 단계적으로 도입.
7. 전체 UI 흐름을 확정한 뒤 가로/세로 전용 최적화를 수행.
8. Lint와 핵심 기능 테스트를 보강하고 Android 15/16 및 다양한 글꼴/화면에서 검증.

## 비용·권리 주의

- ACRCloud 관련 이전 확인: 14일 무료 체험이라고 안내되나 호출 한도/유료 단가는 공개 자료로 확정하지 못했다. 가입 콘솔/영업 견적에서 재확인해야 한다.
- 월 호출 예시(1회 감지당 1회, 30일): DAU 100명×2회=6,000회; 1,000명×2회=60,000회; 10,000명×2회=600,000회. 재시도는 별도.
- 매칭 실패도 과금되는지, 월 기본료/포함량/초과 단가/동시 호출/상업용 조건을 문의한다.
- 운영비는 음악 인식 + 서버 + AI 제목 정리/번역 + 오디오 분석/저장으로 구분한다.
- 가사·음원·커버 이미지·번역·분석 결과의 보관·표시·재배포 권리를 각 제공처 약관으로 확인한다.

### 요구사항과 적용

- 같은 팝업에서 동일 오류 알림은 중복 표시하지 않는다. 팝업이 닫혔으면 새 오류창을 띄우지 않는다.
- 모델 목록 조회만 하던 연결 테스트를 선택 모델의 짧은 실제 생성 요청으로 변경했다. 이 요청도 제공자의 사용량에 포함되며, 성공이 이후 긴 가사 번역의 성공을 보장하지는 않는다.
- 번역·발음 반환을 성공/실패 타입으로 바꿨다. 실패 문구를 문자열로 추측해 저장하지 않으며, 실패와 토큰 한도 중단 결과는 캐시에 저장하지 않는다. 줄 수가 맞지 않으면 임의로 잘라 맞추지 않고 실패를 안내한다.
- 제공자 원문 오류·예외 메시지·키가 담길 수 있는 URL은 사용자에게 그대로 표시하지 않는다.
- 새 분류: `AiFailure.java`, 적용: `LyricsAiClient.java`, `MainActivity.java`.

### ACRCloud 준비 범위
- Host/Access Key/Access Secret 입력·암호화 저장·로컬 형식 검사.
- `RecognitionConfig` → `AudioSampleRecorder` → `AcrCloudClient` → 카탈로그 후보 확인 경로 준비.
- PCM 16 kHz, 모노, 16 bit, 최대 10초. 실제 RIFF/WAV 헤더 생성, 입력 크기 검사. 녹음 파일을 남기지 않음.
- 사용자가 시작/취소하며 앱이 백그라운드로 가면 취소. 기능이 활성화된 빌드에서만 마이크 권한을 요청.
- **현재 `app/build.gradle`의 `ACR_RECOGNITION_ENABLED=false`**. 자격정보를 넣어도 녹음/서버 호출은 하지 않음.
- 나중에 `true`로 바꾸고 재빌드하면 저장한 자격정보를 사용하는 직접 연결 경로가 열림. 절차는 README 참고.
- 실제 ACR 계정·카탈로그·요금/쿼터·실음 인식은 미검증. 운영자 공용 비밀키의 서버 중계는 개인 직접 연결과 별도 배포 과제.

## GPT 선택 적용 및 Gemini 대체 요청 수정
- 원인: 제공자 버튼은 `Draft.provider`만 바꾸고 번역은 저장된 `ai_provider`를 읽었음. 저장 버튼을 누르지 않으면 화면은 GPT여도 마지막 저장된 Gemini로 요청될 수 있었음.
- 제공자 선택을 즉시 저장하고 진행 중 AI/이전 화면 결과를 무효화. 키와 모델은 제공자를 전환할 때 현재 입력을 저장하고, 설정에서 다른 메뉴로 이동할 때 활성 제공자의 입력을 자동 저장. 저장 실패/잘못된 모델이면 안내하고 이동을 막음.
- 전체 설정 저장은 기존대로 표시 언어/표시 항목/ACR 등에도 적용. AI 설정 자동 적용은 ACR 입력 상태와 분리.
- 번역·발음: GPT 선택 → GPT 전용 키/모델/캐시 우선 → 실패하면 Gemini 키가 등록된 경우 Gemini 전용 키/모델/캐시로 한 번 대체. Gemini 선택 시에는 Gemini만 사용. 연결 테스트·모델 조회·선택적 제목 정리는 선택한 제공자만 사용.
- GPT가 성공하거나 GPT 캐시가 있으면 Gemini를 요청하지 않음. Gemini 결과는 Gemini 캐시에만 저장하며 이후 GPT 요청/캐시보다 우선하지 않음.
- 상세창에 실제 결과 제공자 표시. Gemini가 대신 생성하면 GPT 실패 요약과 대체 안내. 둘 다 실패하면 GPT/Gemini 각각의 해결 안내를 한 알림에서 표시하고 설정으로 연결.
- 취소/스레드 중단 및 명시적인 생성 거절·콘텐츠 제한에는 자동 대체하지 않음. 대체 요청이 실패해도 반복하지 않음.
- 대체 요청도 별도 API 사용량을 소모할 수 있음. 특히 GPT 응답 대기 실패는 서버 측 처리 여부를 확정할 수 없으므로 Gemini 대체가 GPT 과금 취소를 의미하지 않음.
- 개인 키/유료 서버 호출 대신 가짜 클라이언트로 요청 순서, 키/모델 매핑, 실제 디스크 캐시 분리와 GPT 우선 복귀를 검증.
